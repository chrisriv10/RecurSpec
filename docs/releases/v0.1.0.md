# RecurSpec v0.1.0

Test whether your error messages actually get users unstuck.

RecurSpec treats a recovery instruction as an executable contract: it puts
your CLI into a known failure state, runs the failing command, executes the
tool own advice inside an isolated workspace, and verifies the user genuinely
recovered, either by retrying the original command or by checking the
intended end state.

## Major features

- Recovery contracts with output-derived, explicit, and structured advice.
- Retry, goal, and custom completion modes.
- Recovery chains with loop detection and ambiguity refusal.
- Safety-first execution: no shell by default, isolated workspaces,
  deny/allow lists, per-attempt verdicts in verbose mode.
- Human, JSON, JUnit, and Markdown reporters; `test --dry-run` planning.
- `validate`, `init`, `explain`, and experimental `discover` commands.
- Programmatic API with TypeScript declarations.

## Real-world validation

Exercised against Git, Cargo, and npm. Notably, real-world testing exposed a
limitation in the original retry-only model (Cargo `init` advice looked like
a dead end) and led to goal-aware verification. See `docs/real-world.md`.

## Safety limitation

The local backend isolates the filesystem but cannot enforce OS-level network
sandboxing, so `safety.network: deny` is advisory until a container backend
exists. Uncertain commands are refused rather than executed.

## Installation

Requires Node.js 22+ and pnpm. Until the package is published to the npm
registry, install the attached release tarball:

```bash
pnpm add -D https://github.com/chrisriv10/RecurSpec/releases/download/v0.1.0/recurspec-0.1.0.tgz
pnpm exec recurspec init
pnpm exec recurspec validate
pnpm exec recurspec test
```
